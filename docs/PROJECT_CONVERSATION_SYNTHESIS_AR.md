# خلاصة محادثات مشروع KU-BO

تاريخ التثبيت: 2026-08-24

هذه خلاصة فنية منقحة للقرارات المتاحة في سياق المشروع ومراجعاته السابقة. ليست
نسخة من المحادثات الخام، ولا تنقل بيانات شخصية أو معرفات Drive. يبقى الأرشيف
الخام خاصًا داخل `AI Rebuild`، وتدخل Git فقط القرارات الفريدة اللازمة لتنفيذ
المشروع.

## الهدف الموحد

`KU-BO` هو مستودع الكود الوحيد لنظام بحث قابل للتدقيق عن أسهم بورصة الكويت.
لا ينشئ Codex مستودع توقعات موازٍ، ولا يساوي بين البحث وبين التوصية أو التنفيذ.

ترتيب البناء الحاكم هو:

1. سلامة الأدلة والحقوق والهوية.
2. Data Plane زمني Point-in-Time.
3. مكتبة أحداث ونتائج ناضجة.
4. Baselines قابلة للتفسير.
5. Walk-forward منقّى مع Embargo وتكاليف وعدم تنفيذ.
6. Champion معتمد ومجمّد، ثم Challenger منفصل.
7. تقييم prospective مختوم قبل أي ادعاء تشغيلي.

لا يُدرّب نموذج أو يعاد ضبط أوزان على بيانات لم تجتز المراحل السابقة.

## المهارات التي تراكمت

- فصل تعريف المصدر عن إمكانية الوصول الفعلية، ثم فصل الوصول عن الدليل المالي.
- وصف طرق الوصول والحقوق والميزانيات وأسباب التوقف بعقود machine-readable.
- حفظ Raw Evidence وSHA-256 ووقت الإتاحة وحقوق الاستخدام قبل التطبيع.
- استخدام `security_code` الرسمي والهوية effective-dated بدل ربط Ticker فقط.
- بناء تقويم جلسات وحالات تعليق وشطب وإعادة إدراج بدل حساب الأيام المدنية.
- فصل Corporate Action terms عن عوامل السعر والاستمرارية والكمية والعائد.
- منع Look-ahead وSurvivorship وتسرب الأحداث بين التدريب والاختبار.
- اعتبار Telegram وIndexSignal مصادر توجيه أو Sentiment فقط، لا مصادر حقيقة.
- استخدام Investing فقط من خلال وصول مشروع أو export مخوّل من المستخدم.
- إبقاء الأسعار العامة المتأخرة خارج طبقة التنفيذ وسعر الدخول الفعلي.
- جعل `WATCH` و`ABSTAIN` نتائج أصلية عند نقص البيانات أو تضاربها.
- اختبار العقود بأمثلة adversarial، ثم اختبار Wheel المثبت وليس شجرة المصدر فقط.
- إدارة عمل Codex من Task branch وDraft PR مع منع الدمج الذاتي والحذف الدائم.

## سلطة المصادر

مصادر الحقيقة الأولى هي بورصة الكويت، هيئة أسواق المال/إفصاح، والشركة المصدرة.
المصادر الإخبارية وMubasher وInvesting المصرح به مصادر بحث مساندة. Telegram
وIndexSignal مسارات اكتشاف وسياق مجتمع فقط. Google Drive تخزين خاص، وليس مصدرًا
أصليًا يمنح الحقوق أو يثبت صحة المحتوى بمجرد وجود الملف.

أي استخدام لموقع محمي يتوقف عند Login أو CAPTCHA أو Paywall أو Rate Limit أو
Robots restriction. لا تدوير حول الحظر، ولا شراء أو تغيير اشتراك دون قرار جديد.

## بروتوكول التدريب المتفق عليه

مجموعة التطوير تحتوي 50 حدثًا أساسيًا و200 حدث ضابط:

- الأحداث الأساسية تشمل قفزة أو هبوطًا مفاجئًا، شطبًا أو تعليقًا مؤثرًا، توزيعًا
  أو منحة أو حقوقًا أو إفصاحًا قويًا؛
- الضوابط تُطابق القطاع والسيولة والتذبذب ونظام السوق وتاريخ الأهلية؛
- 30 جولة هي الخطة الافتراضية؛
- الزيادة حتى 50 جولة لا تحدث إلا بفرضية جديدة مسجلة مسبقًا؛
- لا يُعاد النظر في النتيجة ثم تُختار نافذة أو أوزان تناسبها؛
- بيانات التطوير قد تدخل Regression Replay فقط، لا نتيجة الاختبار المقفل.

الاختبار النهائي المقفل يحتوي 500 إلى 600 حدث جديد بلا تداخل مع أحداث التطوير.
التقسيم Walk-forward مع Purge وEmbargo، والتقييم يشمل التكاليف والسيولة وNon-fill
والامتناع. لا تعني إعادة الجولة 30 أو 50 مرة أن النموذج يصبح جيدًا تلقائيًا؛ معيار
التوقف هو تحسن خارج العينة مع ثبات ومعايرة وعدم تدهور الضوابط.

## معالجة الفجوات

تسلسل معالجة النقص هو:

1. استرجاع الدليل من مصدر مخوّل ومستقل.
2. المصالحة مع المصدر الرسمي والوقت الحقيقي للإتاحة.
3. استخدام Proxy معلن مع Quality Flag إذا كان مسموحًا علميًا.
4. خفض الثقة أو تحويل الحالة إلى `WATCH`.
5. `ABSTAIN` عند تأثير النقص في الهوية أو النتيجة أو التنفيذ.

لا تُملأ فجوة سعرية بالحدس، ولا يُنسخ Snapshot حالي إلى الماضي، ولا تتحول
المعلومة الاجتماعية إلى Corporate Action رسمي.

## دورة العمل الحية المطلوبة

الوقت المرجعي `Asia/Kuwait`. نافذة التشغيل المقترحة 15:07، مع Watchdog عند
15:37. التوقيت المجدول وسيلة تشغيل best-effort وليس ضمانًا بالثانية.

تقرير اليوم يستخدم فقط Champion مجمّدًا ومعتمدًا من جلسة سابقة. بعد ختم التقرير
يمكن إدخال النتائج الناضجة السابقة وتدريب Challengers. لا يحق لأي Challenger
مدرّب في اليوم نفسه إصدار تقرير ذلك اليوم أو ترقية نفسه.

المنتجات اليومية المربوطة بكتالوج المستودع هي:

- `three_session_rank`: ثلاث جلسات؛
- `five_session_weekly_swing`: خمس جلسات؛
- `twenty_one_session_monthly_swing`: 21 جلسة؛
- `sixty_three_session_quarter_rank`: 63 جلسة.

النتائج المسموحة قبل اجتياز البوابات هي `RESEARCH_CANDIDATE` و`WATCH` و`ABSTAIN`.
سعر دخول أو خروج تنفيذي يحتاج Feed أو Broker export مخولًا وتوقيتًا قابلًا
للتنفيذ. السعر العام المتأخر لا يملأ هذا الدور.

## التطوير المستمر

التطوير المستمر يعني Champion-Challenger مع سجل تجارب، لا تعديل الإنتاج مباشرة:

1. يسجل النظام الفرضية والفجوة والدليل الجديد.
2. يبني Challenger في Artifact منفصل.
3. يعيد الاختبارات الزمنية والمقارنة مع Baseline وChampion.
4. يكتب اقتراح تغيير في Task branch وDraft PR.
5. لا يرقّي النموذج أو يدمج الكود دون البوابات والقرار المطلوب.

بهذا الأسلوب يتطور المستودع يوميًا من أخطائه وبياناته الجديدة، بينما يظل تقرير
اليوم قابلًا لإعادة الإنتاج ولا يتغير بأثر رجعي.

## قرارات لا تُبعث من جديد

- لا إعادة استخراج مجموعة أسعار Factor 9 لمجرد وجود جولة جديدة.
- لا إعادة حساب Score السعر القديم وتسميته نموذج استثمار نهائي.
- لا تدريب على OCR أو Auto-label بوصفه حقيقة.
- لا خلط 250 حدث تطوير داخل نتيجة الاختبار المقفل.
- لا ادعاء دقة من Synthetic tests أو Recorded fixtures.
- لا توصيات شراء تلقائية أو دمج تلقائي للكود.
- لا تخزين محادثات خام أو معرفات Drive أو بيانات خاصة في GitHub.

العقود التنفيذية لهذه الخلاصة موجودة في
`config/codex_live_bootstrap.json` و`schemas/codex-live-bootstrap.schema.json`
و`schemas/champion-freeze-manifest.schema.json`.
