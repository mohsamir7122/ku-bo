# سياسة اختيار وفحص المصادر

تاريخ التحقق من القواعد الرسمية: 7 أغسطس 2026.

## السؤال الصحيح لكل مصدر

لا نسأل فقط «هل الصفحة تفتح؟». نسأل خمسة أسئلة مستقلة:

1. هل طريقة الوصول مشروعة ومصرحًا بها؟
2. هل المصدر صاحب سلطة على هذا النوع من الحقائق؟
3. هل البايتات المطلوبة حُفظت فعلًا ويمكن إعادة التحقق منها؟
4. هل التوقيت والتغطية مناسبان للمنتج؟
5. هل البيانات Evidence تاريخي أم Execution-grade؟

الفشل في أي سؤال يبقي القدرة محجوبة، حتى لو نجح HTTP request.

## المصادر الرسمية

### بورصة الكويت

الاستخدام المسموح:

- Security master والحالات والإيقاف والتقويم.
- بيانات EOD وإجماليات السوق عند اكتمالها وحفظها ومصالحتها.
- الإفصاحات والإجراءات الرسمية عند توفرها.
- قواعد الجلسة والحدود السعرية.

الحدود:

- الموقع العام يصرح بأن بيانات التداول متأخرة 15 دقيقة.
- التأخر لا يمنع استخدام Completed-session EOD، لكنه يمنع إثبات دخول حي.
- الوصول الحالي المتقطع لا يثبت Historical coverage.
- Page availability لا تساوي Parser stability أو Permission للAutomation.

### CMA Kuwait وiFSAH

الاستخدام المسموح:

- الإفصاحات والملفات المنظمة XBRL.
- قرارات وتعليمات وحالات تنظيمية.
- Cross-check وتصحيحات الإفصاح.

الحدود:

- إفصاح منظم لا يعطي Bid/Ask أو Queue أو Fill.
- فترة الانتقال بين قنوات النشر تحتاج Query ledger على القناتين عند اللزوم.

### علاقات المستثمرين الرسمية

تستخدم للتقارير المالية والعروض والإعلانات الأصلية، لكن لا تُفعّل عائلة `issuer_ir_registry_unconfigured` حتى تسجيل Domain رسمي لكل شركة والتحقق منه.

## المصادر الثانوية

Investing وTradingView وArgaam وMubasher وYahoo وMarketScreener والصحافة لا تثبت وحدها Official EOD أو Corporate Action factor. تستخدم في:

- اكتشاف Mover أو خبر.
- مقارنة صف أو تاريخ.
- سياق القطاع والاقتصاد.
- العثور على الأصل الرسمي.

إذا اختلف مصدر ثانوي مع الرسمي، لا نعدل الرسمي بصمت؛ نسجل Conflict ونبحث عن Correction أو اختلاف وحدة/تاريخ/هوية.

## Social وTelegram والمنتديات

تستخدم في:

- الانتباه.
- سرعة الانتشار.
- تنوع الحسابات.
- اكتشاف إشاعة أو Lead.

لا تستخدم في:

- إثبات عقد أو أرباح أو توزيع.
- إثبات سعر دخول.
- مضاعفة Event Count بسبب Reposts.

المحتوى الخاص أو غير المصرح به خارج النطاق.

## مزود التنفيذ

تعريف `authorized_market_feed_unconfigured` قالب محجوب. تفعيله يحتاج عقد مصدر جديد يحدد:

- اسم المزود وDomain الفعلي.
- Access mode وEntitlement.
- Delay/SLA.
- Auction/Intraday/L1/Execution fields.
- حقوق الاحتفاظ وإعادة الاستخدام.
- Evidence bytes وProvider timestamps.

Approved data vendors أو Broker feed قد يحل المشكلة، لكن مجرد وجود مزود في قائمة رسمية لا يثبت أن المشروع يملك اشتراكًا أو Entitlement.

## التخزين

Google Drive أو أي مخزن Artifact يحفظ الملفات والختم، لكنه لا يتحول إلى مصدر سوق. مصدر الملف يبقى البورصة أو CMA أو المزود أو الشركة، ويظل Hash الخام مرتبطًا بذلك المصدر.

## القواعد الرسمية التي يعتمد عليها الكود

الروابط والادعاءات التشغيلية مسجلة آليًا في `research/official_rules_registry.json`. أهمها:

- تأخير بيانات التداول العامة 15 دقيقة.
- جلسة الافتتاح والتداول المستمر والإغلاق وTrade at Last وفق الصفحة الرسمية الحالية.
- حدود الورقة +10% و-5% وآلية Auction المرتبطة بها.
- وجود قائمة رسمية لمزودي البيانات المعتمدين.
- إلزام نظام iFSAH/XBRL حسب قرار CMA المنشور.

يجب إعادة فحص هذه القواعد عند كل Release يؤثر في Execution أو Calendar، لأن القواعد والأوقات قد تتغير.
